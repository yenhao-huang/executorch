# Portable kernel: native_layer_norm_backward.out

Related issue: [ExecuTorch #11337](https://redirect.github.com/pytorch/executorch/issues/11337)

## Summary

ExecuTorch had a portable `native_layer_norm.out` but no backward kernel.
This adds `native_layer_norm_backward.out`, which produces `grad_input`,
`grad_weight` and `grad_bias` with ATen CPU semantics for Float, Double,
Half and BFloat16. Half and BFloat16 accumulate in float.

Before starting, the issue had no comments, no assignee and no linked
pull request, and upstream main (`ec5e3cf21f`) had neither the kernel nor
a `functions.yaml` entry.

## Semantics

Schema (verified against torch `2.14.0+cpu`):

```text
native_layer_norm_backward.out(Tensor grad_out, Tensor input, SymInt[] normalized_shape,
  Tensor mean, Tensor rstd, Tensor? weight, Tensor? bias, bool[3] output_mask, *,
  Tensor(a!) out0, Tensor(b!) out1, Tensor(c!) out2) -> (Tensor(a!), Tensor(b!), Tensor(c!))
```

With `M` the product of the leading dimensions and `N` the product of the
normalized dimensions, the kernel follows ATen's
`LayerNormBackwardKernelImplInternal`. Each row computes
`ds = sum(dy * gamma * x)` and `db = sum(dy * gamma)`, then
`dx = rstd * dy * gamma + b * x + c` where
`b = (db * mean - ds) * rstd^3 / N` and `c = -b * mean - db * rstd / N`.
`grad_weight[j]` is the sum over rows of `dy * (x - mean) * rstd`, and
`grad_bias[j]` is the sum of `dy`. A missing weight means `gamma = 1`.

Behaviour verified against ATen in torch:

| Case | ATen | This kernel |
| --- | --- | --- |
| `output_mask[k]` false | Output is undefined (the `.out` overload rejects a defined out tensor) | Output is not resized or written, as in `convolution_backward.out` |
| `output_mask[1]` true without weight, or `output_mask[2]` true without bias | Error | `InvalidArgument` |
| `M == 0` | `grad_weight` and `grad_bias` are zeros | Zeros |
| mean/rstd shape | Read as `M` contiguous values; `(M, 1...)` and flat both accepted | Must have `M` elements |
| `grad_out` shape | Only element count is used | Must match the input shape (stricter) |

Validation reuses `check_layer_norm_args`, whose output parameters became
`const Tensor&` so it can validate `grad_out`, `mean` and `rstd`. This is
source-compatible with the three existing callers. Like the forward
kernel, the input must use the default dim order.

## Not verified

- ATen-mode and Buck builds. The test is registered in `targets.bzl` for
  `aten` and `portable`, and cases that depend on ExecuTorch-only behaviour
  (masked-off outputs, the stricter shape checks, dim order, static resize)
  are skipped in ATen mode. Only CMake was run.
- Full `lintrunner`.
- Performance. The `grad_weight`/`grad_bias` reduction walks columns
  without a scratch buffer, so it reads with stride `N`.

Local test success does not guarantee CI success.
