`fix/24671-broadcast-output-strides` branch containing this report.

## Problem and fix

During broadcasting, `BroadcastIndexesRange` returns a logical iteration
counter at index zero. Channels-last outputs need a physical offset computed
from their strides. Using the counter as that offset swaps output values.
For multiplication of logical inputs `[1, 2, 3, 4]` and channel multipliers
`[10, 20]`, the expected logical result is `[10, 20, 60, 80]`.
Its channels-last storage is `[10, 60, 20, 80]`.

The binary and ternary helpers, specialized and dtype-converting elementwise
paths, and optimized `where` now pass the output as an additional iterator
input and store through its physical offset. Parallel loop bounds still use
the logical counter. The dense traversal and vectorization shortcuts require
matching strides on corresponding non-singleton dimensions, in addition to
matching shapes after leading singleton dimensions are removed.

Review `broadcast_indexes_range.h` first, then the consumers in
`broadcast_util.h`, `elementwise_util.h`, and optimized `op_where.cpp`.
The utility and operator regressions cover those paths. CMake and Buck both
register the new utility test file; only CMake was executed here.

Before the fix, the initial seven utility/iterator regression cases were
built against the baseline production implementation. Six failed and one
passed. This historical run used the first revision of the regression tests;
additional cases were added afterward. It was performed in the development
worktree before restoring the fixed implementation, not in a second checkout.
The baseline build and output logs remain at
`/tmp/et-24671-baseline-build.log` and
`/tmp/et-24671-baseline-tests.log`.

The command used for that baseline run was:

```bash
/tmp/et-24671-cmake/kernels/portable/cpu/util/test/kernels_portable_cpu_util_test \
  --gtest_filter='ElementwiseUtilTest.*:BroadcastIndexesRangeTest.SameShapeDifferentLayouts:BroadcastIndexesRangeTest.ChannelsLastOutputAsInput'
```

The failures were `SameShapeDifferentLayouts` in `BroadcastIndexesRangeTest`
and `BinaryChannelsLastBroadcast`, `TernaryChannelsLastBroadcast`,
`SpecializedChannelsLastBroadcast`, `DtypeConvertingChannelsLastBroadcast`,
and `VectorizableSameShapeDifferentLayouts` in `ElementwiseUtilTest`.
They were value/index mismatches, not build or dependency failures.
All these cases pass in the fixed utility suite.
