## 2. Diagnosis and implementation

The baseline PlaceholderObserver uses per_tensor_affine and produces one dynamic
scale/zero point for the complete activation tensor. The new configuration uses
torchao's AffineQuantizedPlaceholderObserver with PerToken and asymmetric INT8
mapping. Setting a per-channel qscheme alone would not implement this conversion.
Dynamic INT8 defaults to per-token; `act_per_token=False` retains the previous
configuration. `is_dynamic=False` remains weight-only; INT4 defaults are unchanged.

The new `et_vk.linear_dq8ca_q8csw` reference explicitly chooses qparams, quantizes,
dequantizes and applies per-channel quantized weights. Fusion verifies the chooser,
Q/DQ parameters, feature block, dtypes, weight axis/zero points and addmm scaling.
It recognizes the view/unsqueeze forms introduced by linear decomposition.
The original chooser disappears only when it has no remaining consumers.

The runtime computes per-row qparams and packed activations in a Vulkan reduction
shader, then uses INT32 accumulation, activation zero-point correction, weight
scales and optional bias in a second shader. All leading dimensions are flattened
into independent rows. Contiguous activation buffers and existing packed weight
textures/buffers have explicit resize support. The no-dot variant still computes
quantized integer products on Vulkan. The initial implementation supports float32
inputs with a positive feature count divisible by four.

For the static and dynamic INT4 comparison, disabled decorators were temporarily
removed. Dynamic INT4 additionally required the installed torchao argument name
`weight_granularity` instead of the test's obsolete `granularity`; both runs used
seed 22431. Five modified Python implementation files were temporarily restored
to their baseline contents for the comparison, then restored to the fix. The
compiled runtime contained the added, unused INT8 operator; existing INT4/static
native sources were unchanged. The weight-only baseline comparison used the same baseline Python restoration. The failing INT4 output values match exactly
between both runs (maximum reported absolute mismatch 0.014373). This failure is
pre-existing and outside this issue. All temporary test edits were removed.

The fixed demo is the same token-independence command above plus the serialized
runtime test. The runtime tests assert that the Vulkan graph contains the new
operator and excludes the standalone chooser, then compare the loaded program
against the converted quantized graph at rtol=atol=2e-4. They exercise different
inputs on the same runtime, not just the calibration data. Dynamic token lengths
are 3, 1, 7 and 2, with batch size 2. The Vulkan device reports shaderIntegerDotProduct=true (without signed packed-dot hardware acceleration), so normal dispatch exercises the dot shader and the override exercises the explicit integer fallback. The C++ reference independently implements
rounding/clamping/qparams and tests normal dispatch and forced no-dot dispatch,
K=4/64/256 and K exceeding the texture packing limit, with and without bias.
