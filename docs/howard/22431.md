## 2. Diagnosis and implementation

The baseline PlaceholderObserver uses per_tensor_affine and produces one dynamic
scale/zero point for the complete activation tensor. The new configuration uses
torchao's AffineQuantizedPlaceholderObserver with PerToken and asymmetric INT8
mapping. Setting a per-channel qscheme alone would not implement this conversion.
Dynamic INT8 defaults to per-token; `act_per_token=False` retains the previous
configuration. `is_dynamic=False` remains weight-only; INT4 defaults are unchanged.

The new `et_vk.linear_dq8ca_q8csw` reference explicitly chooses qparams, quantizes,
dequantizes and applies per-channel quantized weights. Fusion verifies the chooser,
Q/DQ parameters, feature block, dtypes, weight axis/zero points and addmm scaling.
It recognizes the view/unsqueeze forms introduced by linear decomposition.
The original chooser disappears only when it has no remaining consumers.

The runtime computes per-row qparams and packed activations in a Vulkan reduction
shader, then uses INT32 accumulation, activation zero-point correction, weight
scales and optional bias in a second shader. All leading dimensions are flattened
into independent rows. Contiguous activation buffers and existing packed weight
textures/buffers have explicit resize support. The no-dot variant still computes
quantized integer products on Vulkan. Lowering supports float32 graphs with a
positive feature count divisible by four. The review revision also supports the
force_fp16 compile option with typed half storage and float32 activation qparams.

## Shared activation correction after round-two review

Claude accepted `8c8043807f` without executing tests, based partly on the incorrect
assumption that two projections cannot share PT2E activation observers. The parent
then exported two distinct Linear(32,16) modules reading the same input. Conversion
produced one chooser/Q/DQ, with two users of dequantize_affine. Static (3,32)
execution passed, but a dynamic token bound of 65540 left the texture-limited
chooser outside the delegate and failed with a missing choose_qparams_affine out
variant. This is a concrete gap in the new per-token feature. The parent's
act_per_token=False control also failed, on a pre-existing missing
dequantize_per_channel runtime operation; it is not evidence of a working legacy
configuration or a demonstrated legacy regression.

The correction checks qparam consumption across all compatible per-token linear
matches that satisfy delegation policy. A sibling projection is an internal
consumer only when it can participate in fusion. External qparam users and
incompatible or excluded projections retain normal standalone support checks.
The common operator/module policy check runs before the fusion fast path, so
fusion cannot bypass allowlist/blocklist exclusions. Each fused projection still
computes the same token-local activation quantization on Vulkan; quantization is
not disabled or moved to a CPU numerical substitute.

The new registered runtime regression first asserts exactly one chooser, one Q
and one DQ, and two DQ consumers. It returns both projections and their sum,
asserts two fused Vulkan linear operations and no standalone chooser, and compares
all three outputs against the converted reference at rtol=atol=2e-4. It covers
static input and a dynamic runtime with token counts 3, 65536 and 2, retaining
max=65540. Before the correction it fails with the same missing out variant;
after the correction it passes. The parent's original sum-only reproduction also
passes, including the large dynamic case.

A registered partition test covers nine cases: compatible shared projections,
external qparams, an incompatible projection, operator and chooser blocklists,
operator and chooser allowlists, and selective module allow/block lists. Module
cases use controlled provenance metadata to exclude one projection while asserting
that the other remains supported. The existing single-consumer rejection test is
retained. Native runtime/shader sources and installed build outputs are unchanged.
