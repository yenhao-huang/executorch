# Portable kernel: scatter_reduce.two_out

Related issue: [ExecuTorch #11330](https://redirect.github.com/pytorch/executorch/issues/11330)

## Summary

`scatter_reduce.two_out` had no portable kernel, so a graph using
`torch.scatter_reduce` could not run on the portable kernel library. This adds
the kernel for all five reduce modes (`sum`, `prod`, `mean`, `amax`, `amin`)
and both `include_self` settings, following ATen CPU semantics.

This fork PR was opened on an older base (`base/upstream-main-91b2e90`). It
was refreshed in place by merging upstream main `ec5e3cf21f` into the branch
and retargeting the PR to `base/upstream-main-ec5e3cf21f`. History was not
rewritten.

## Algorithm

```text
Validate reduce, dtypes, ranks, index sizes and index bounds
(check_scatter_add_args); reject mean on Bool, as ATen does.
Resize out to self and copy self into out.
If index is empty, stop.

If include_self is false:
    For every index element, set its target out position to the mode identity
    (0 for sum/mean, 1 for prod, -inf or dtype lowest for amax,
    +inf or dtype max for amin).

For every index element:
    target = out position (index value along dim, index coordinates elsewhere)
    out[target] = reduce(out[target], src[same coordinates as index])
    amax/amin propagate NaN from either operand.
    For mean, count contributions per position in a temp buffer that starts at
    1 when self is included and 0 otherwise.

For mean, divide every position with count > 1 by its count; integer dtypes
use floor division.
```

## Changes compared with the earlier version of this PR

The earlier commit `3c9d6ec26f` was reviewed against ATen and reworked:

| Change | Reason |
| --- | --- |
| Integer `mean` uses `utils::floor_divide` | ATen divides integer outputs with `rounding_mode="floor"`. `-9 // 2` must be `-5`; C++ `/` gives `-4`. |
| `amax`/`amin` propagate NaN from `src` | ATen's scatter max/min returns a NaN `src` value. `std::max(acc, nan)` dropped it. |
| `mean` on Bool is rejected | ATen raises "not implemented for 'Bool'" for this case. |
| Identity is scattered directly for `include_self=False` | Same approach as ATen. A temp buffer is now needed only for `mean` counts, not for every mode. |
| `kernels/test/TempMemoryAllocator.h` removed; `op_topk_test.cpp` restored | They were an extraction shared with a separate sort-kernel PR. The new test gives `context_` a fixed-buffer `MemoryAllocator`, so this PR no longer depends on that PR or touches topk. |
| `build_variables.bzl` lists the source; `math_util` dependency added | Matches the current upstream convention for new portable kernels. |

Suggested review order:

1. `kernels/portable/cpu/op_scatter_reduce.cpp`
2. `kernels/test/op_scatter_reduce_test.cpp`
3. Registration files

### Baseline

On upstream main `ec5e3cf21f`, `git grep scatter_reduce` over
`kernels/portable`, `kernels/aten/functions.yaml`, `kernels/test` and `shim_et`
finds nothing (exit code 1), and `kernels/portable/cpu/op_scatter_reduce.cpp`
does not exist. The operator is unregistered. The new test cannot compile on
that baseline because codegen does not declare `scatter_reduce_outf`. No
baseline build was run, so there is no runtime failure log.
